# Руководство по внесению изменений

Этот документ описывает процесс добавления новых материалов в репозиторий ITOps Labs.

## 📝 Формат материалов

### Лабораторные работы

Каждая лабораторная работа должна содержать:

1. **README.md** с структурой:
   ```markdown
   # Название лабораторной
   
   ## Цель
   Описание цели работы
   
   ## Предварительные требования
   - Знание X
   - Установленное ПО Y
   
   ## Инструкция
   Пошаговое выполнение
   
   ## Конфигурационные файлы
   Ссылки на конфиги
   
   ## Задание для самостоятельной работы
   
   ## Контрольные вопросы
   ```

2. **Конфигурационные файлы** (при необходимости)
3. **Docker Compose** (если применимо)
4. **Скрипты** для автоматизации

### Wiki статьи

Статьи wiki должны быть написаны в формате Markdown и содержать:
- Четкое описание темы
- Примеры кода и конфигураций
- Ссылки на связанные темы
- Практические примеры

### Проекты

Проекты должны включать:
- `README.md` с описанием
- Исходный код
- Конфигурационные файлы
- Инструкцию по запуску

## 🔖 Стиль кода

### Node.js
- Использовать ES6+ синтаксис
- Следовать стандартным соглашениям именования
- Добавлять комментарии к сложным участкам

### Python
- Следовать PEP 8
- Использовать type hints где уместно
- Добавлять docstrings

### Bash скрипты
- Использовать `set -euo pipefail`
- Комментировать сложные команды
- Проверять наличие зависимостей

## 📁 Именование файлов

- Используйте lowercase с дефисами: `my-file.md`
- Избегайте пробелов в именах файлов
- Расширения должны соответствовать типу файла

## ✅ Чеклист перед отправкой

- [ ] Материалы проверены на работоспособность
- [ ] Код отформатирован согласно стандартам
- [ ] README обновлен при необходимости
- [ ] Нет чувствительных данных в коде
- [ ] .gitignore настроен корректно

## 🤝 Процесс review

1. Создайте issue с описанием планируемых изменений
2. Создайте ветку от `main`
3. Внесите изменения
4. Создайте Pull Request
5. Дождитесь review
